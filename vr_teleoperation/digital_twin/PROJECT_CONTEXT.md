# 🤖 Digital Twin 프로젝트 컨텍스트

## 📅 2025-01-17 - Digital Twin 기반 양팔 텔레오퍼레이션 구현

### 🎯 프로젝트 목표
VR 텔레오퍼레이션을 실물 로봇에 안전하고 정교하게 적용하기 위한 Digital Twin 시스템 구현

### 💡 핵심 아이디어
```
기존: VR → MuJoCo → 오프셋 기반 → 실물 (불안정)
개선: VR → MuJoCo(동기화) → 실물 (안전하고 정교)
```

MuJoCo를 실물 로봇의 "디지털 쌍둥이"로 만들어 시각적 피드백과 안전 검증을 수행

## 🔍 문제 분석

### 기존 시스템의 문제점
1. **왼팔이 튀는 현상**: 오프셋 기반 제어의 불안정성
2. **조인트 인덱스 혼란**: joint_states 토픽 순서 문제 (j1=idx7, j2=idx8, j3=idx1, j4=idx5)
3. **이중 변환 오차**: VR델타 → MuJoCo → 오프셋 → 실물 과정에서 오차 누적

### 해결 방향
- 실물과 MuJoCo를 먼저 완벽히 동기화
- 동기화된 MuJoCo에서 검증된 움직임만 실물로 전송
- 충돌 감지, 한계 체크를 MuJoCo에서 수행

## 🔧 기술적 세부사항

### 오프셋 값
```python
# 왼팔 (test2에서 측정 완료)
left_arm_offsets = [0.0, -0.43, 1.94, -0.42]

# 오른팔 (측정 예정, 왼팔과 유사할 것으로 예상)
right_arm_offsets = [측정 필요]
```

### 하드웨어 구성
- **왼팔**: Dynamixel ID 11-15
- **오른팔**: Dynamixel ID 21-25
- **포트**: /dev/ttyACM0 또는 /dev/ttyUSB0
- **ROS2 토픽**:
  - `/arm_controller/joint_trajectory` (왼팔)
  - `/right_arm_controller/joint_trajectory` (오른팔)
  - `/joint_states` (양팔 통합)

### 동기화 방식
1. **Teaching 모드**: 실물 로봇 토크 OFF → 손으로 움직임 → MuJoCo 따라감
2. **오프셋 계산**: 실물 홈 포지션 값 - MuJoCo 홈 포지션 값
3. **실시간 동기화**: 실물 값 - 오프셋 = MuJoCo 값

## 🚨 우려사항 및 해결책

### 1. 하드웨어 런치파일 안정성
- **우려**: 개인적으로 수정한 양팔 런치파일의 안정성
- **해결**: 이미 오프셋 기반으로 작동 확인, ROS2 토픽만 사용하면 안정적

### 2. 3D 프린팅 부품 오차
- **우려**: 구매한 OMX가 아닌 자체 제작 부품의 기구학적 오차
- **해결**: Teaching으로 정확한 오프셋 측정, 백래시 보상 추가 가능

### 3. 레이턴시
- **우려**: MuJoCo → 실물 전송 지연
- **해결**: 20Hz 제어 주기, 필요시 Direct Dynamixel SDK 사용

### 4. 양팔 오프셋 차이
- **예상**: 왼팔과 오른팔 오프셋이 거의 동일할 것
- **검증**: 먼저 왼팔 오프셋으로 테스트 후 필요시 조정
